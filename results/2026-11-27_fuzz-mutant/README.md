# 정확성 시험의 검출력 확인 (변이 시험)

- 목적: `bench/cache_fuzz.c`가 캐시 버그를 실제로 잡는지 확인. 버그가 있는 커널에서 시험이 실패해야 "불일치 0"이 의미가 있다.
- 넣은 버그: 캐시를 만들 때 필터 여러 개의 결과를 합치는 규칙(`seccomp_cache_prepare_arch()`)에서
  `if (ACTION_ONLY(prev_ret) < ACTION_ONLY(ret))` → `<=`. 같은 등급의 결과끼리는 나중 필터가 이겨야 하는데 먼저 필터가 이기게 됨(errno 값 등 DATA가 달라짐)
- 커널: 6.18 + patches/filter-cache 0001~0007 + 위 한 줄 변경
- 실행: `sudo /tmp/cache_fuzz 5000` (mode 0 = 필터 실행을 정답으로 mode 1·2 비교)

## 결과

```
불일치: seed 4992, 필터 3개, nr 156: mode0 errno 37, mode2 errno 9
비교 50000건: 성공 8372, errno 14024, TRAP 7659, KILL 19945
불일치 2311건 → 실패
```

- 버그 커널: 5만 건 중 2,311건 불일치(4.6%)로 실패 → 시험이 이 버그를 잡는다.
- 변경을 되돌린 커널(0001~0007 그대로): 불일치 0건 → 통과.
- 예시 불일치는 필터 3개에서 같은 ERRNO 등급끼리 합쳐질 때, 정답(나중 필터의 errno 37) 대신 먼저 필터의 errno 9가 나온 경우다.
