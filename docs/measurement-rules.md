# 측정 규칙 v1

3차 회의 결정 7("각자 측정 스크립트를 만들고, 한 사람이 같은 VM에서 전부 돌린다")을 구체화한다.
보고서에 들어가는 수치(정식 측정)는 모두 이 규칙을 따른다. 담당: 권민찬.

## 1. 누가, 어디서

- 정식 측정은 **권민찬이 한 VM에서 전부** 돌린다. VM 설정(vCPU 수, 메모리)은 측정 기간 동안 바꾸지 않는다.
- 각자는 자기 VM에서 스크립트가 도는지만 확인한다. 그 결과를 올릴 때는 결과 폴더 이름에 `prelim`을 붙인다
  (예: `results/2026-11-28_notify-rt-prelim/`). 예비 결과끼리, 또는 예비와 정식 결과를 수치로 비교하지 않는다.

## 2. 커널과 조건

- develop의 패치를 **모두** 넣은 커널 하나로 잰다. 조건은 재부팅 없이 sysctl과 측정 명령의 인자로 바꾼다.
  커널이 다르면 조건 말고도 달라지는 것이 많아서(빌드, 부팅 상태, 캐시) 차이가 어디서 왔는지 가릴 수 없다.

| 조건 | sysctl | 측정 명령 인자 | 뜻 |
|---|---|---|---|
| F0 | `kernel.seccomp.cache_mode=0` | | 캐시 없음 |
| F1 | `kernel.seccomp.cache_mode=1` | | 허용 캐시만 (현재 리눅스) |
| F2 | `kernel.seccomp.cache_mode=2` | | 허용 + 거부 캐시 (D) |
| B0 | `kernel.seccomp.auto_sync=0` | | 기본 동작 |
| B1 | `kernel.seccomp.auto_sync=0` | `--sync-mode` | 감독 프로그램이 동기 플래그를 켬 |
| C | `kernel.seccomp.auto_sync=3` | | 자동 동기 모드 (C) |

- `auto_sync`는 이름이 확정되기 전의 제안이다. 확정되면 이 표와 `bench/conds/notify.conds`를 고친다.
- 패치를 넣지 않은 6.18 원본과의 비교가 필요하면, 원본 커널로 따로 재고 별도 결과 폴더에 둔다.
  이 비교는 "꺼 둔 스위치가 비용을 만들지 않는가" 확인용이고, 조건 사이의 비교는 같은 커널 안에서만 한다.

## 3. 반복과 순서

- 한 비교 묶음(예: B0, B1, C)의 조건을 **매 회 무작위 순서로** 한 번씩 돌리고, 이를 **10회** 반복한다.
  조건을 고정된 순서로 돌리면 시간이 지나며 생기는 변화(온도, 다른 VM의 부하)가 특정 조건에 몰린다.
- 첫 회 전에 예열로 한 번 돌리고 기록하지 않는다.
- 한 번의 측정은 반복 루프 전체를 한 번에 잰다(측정 호출 자체의 비용을 줄이기 위해).
  예: `perf bench sched seccomp-notify`는 기본 100만 번을 한 번에 잰다.

## 4. 환경

- 측정 중에는 다른 작업(빌드, 브라우저, 다른 VM)을 끈다. 끄지 못한 것은 결과 README의 메모에 적는다.
- CPU 고정(`taskset`)은 기본으로 하지 않는다. 알림 경로는 어느 CPU에서 깨어나는지가 측정 대상이기 때문이다.
  고정한 실험은 조건 이름에 표시한다(예: `B0-pin`).

## 5. 측정 명령과 실행기

- 각자 만드는 것은 **측정 명령 하나**다. 한 번 실행에 한 번 재고, 표준 출력에 `지표,값` 줄만 낸다.
  ```
  usecs_per_op,40.78
  ops_per_sec,24523
  ```
- 조건 바꾸기, 반복, 순서 섞기, 기록은 공통 실행기 `scripts/run_bench.sh`가 한다.
  ```
  scripts/run_bench.sh <조건 파일> <결과 이름> [반복=10] -- <측정 명령...>
  scripts/run_bench.sh bench/conds/notify.conds notify-rt -- bench/notify_perf.sh
  ```
- 조건 파일(`bench/conds/*.conds`)은 한 줄에 `이름 sysctl목록 [붙일 인자...]`다. sysctl이 여럿이면 쉼표로 잇고, 없으면 `-`.
- 실행기는 시작 전의 sysctl 값을 저장해 두었다가 끝나면(중간에 멈춰도) 되돌린다.
- 필터 경로(F1, F2)의 기존 측정 `scripts/bench_modes.sh`도 같은 규칙(교차 10회, 무작위 순서)으로 잰 것이다.

## 6. 결과

- `results/<날짜>_<이름>/` 아래 `bench.csv`(`condition,run,metric,value`), `summary.txt`, `README.md`.
  실행기가 셋 다 만든다. README에는 커널, 기계, 저장소 커밋, 조건, 회차별 순서가 자동으로 들어가고, 메모는 사람이 채운다.
- 대표값은 **중앙값**으로 보고하고, 최소·최대를 함께 적는다. 튀는 값 하나가 평균을 크게 흔들 수 있어서다.
  평균도 summary.txt에 남긴다.
- 수치 비교는 **같은 결과 폴더 안에서만** 한다. 다른 날이나 다른 커널 빌드의 결과를 나란히 놓지 않는다.
